Documentation / CLI reference

CLI — files over P2P

Publish and pull files through the same Hyperdrive every node already runs — no separate file server.

pyrusllm send

Publish a file or folder into this node's Hyperdrive and announce it on the DHT. Prints a qvac:// link.

pyrusllm send <path> [--as <name>]
The process stays running on purpose. Hypercore is not store-and-forward: there is no server holding the file. The bytes come out of your machine, so it must stay on while the other side downloads.

pyrusllm fetch

Download a file published by another machine.

pyrusllm fetch qvac://<key>/<path> [--out <dir>] [--timeout <s>]
Every block is verified against the drive's merkle root as it arrives, so a file tampered with midway cannot complete. What the key does not prove is whose it is — that depends on the channel the link arrived through.

pyrusllm files

List the files published by this node, or by a peer.

pyrusllm files [--link qvac://…] [--timeout <s>]

With --link it lists a remote drive without downloading the content: Hyperdrive metadata replicates separately from the blobs.
